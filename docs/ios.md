# iOS App — Altis Cashflow

## Overview

The iOS app is a SwiftUI companion to the Altis cashflow platform. It reads the
same Supabase backend as the Next.js web app, authenticating with the demo
accounts and displaying the 13-week weather-aware cashflow forecast and company
data via PostgREST (RLS-gated).

The app lives under `ios/` (built in parallel with the web app) and is **not
committed to the repo** beyond source code — build output and generated
credential files are gitignored.

## Credentials: Secrets.swift

The app reads the Supabase URL and anon key from a generated Swift file that is
**gitignored** (`ios/Altis/Secrets.swift`). It must be created before building.

Generate it from `.env.local`:

```bash
# from repo root
python3 - <<'EOF'
import re, pathlib

env = {}
for line in pathlib.Path(".env.local").read_text().splitlines():
    line = line.strip()
    if line and not line.startswith("#") and "=" in line:
        k, v = line.split("=", 1)
        env[k.strip()] = v.strip()

url = env["NEXT_PUBLIC_SUPABASE_URL"]
# The iOS app uses the anon key. Derive it from the JWT in SUPABASE_SERVICE_ROLE_KEY
# or paste it manually below if you have it separately.
anon_key = env.get("NEXT_PUBLIC_SUPABASE_ANON_KEY", "PASTE_ANON_KEY_HERE")

out = pathlib.Path("ios/Altis/Secrets.swift")
out.write_text(f'''// AUTO-GENERATED — do not commit. Regenerate with `python3 scripts/gen_secrets.py`.
enum Secrets {{
    static let supabaseURL = "{url}"
    static let supabaseAnonKey = "{anon_key}"
}}
''')
print(f"Written {out}")
EOF
```

The anon key is the `NEXT_PUBLIC_SUPABASE_ANON_KEY` from your Supabase project
settings → API → Project API keys. It is safe to expose in the client because
RLS blocks all unauthenticated and unauthorised access.

## Authentication

The app signs in with any of the 5 demo accounts using email/password via
`supabase-swift`'s `auth.signIn(email:password:)`. The shared password is
**`AltisDemo!2026`**.

| Email | Role |
|---|---|
| `cfo@altis.demo` | cfo |
| `board@altis.demo` | board |
| `opco@altis.demo` | opco |
| `project@altis.demo` | project |
| `admin@altis.demo` | admin |

After sign-in, the JWT is attached automatically to PostgREST requests, and RLS
permits `SELECT` on all `altis_*` tables.

## Data the app reads

The app queries these Supabase tables via PostgREST (all RLS-gated to
authenticated users):

| Table | Purpose in the app |
|---|---|
| `altis_forecast_weeks` | 13-week cashflow forecast rows (scenario × company × week) |
| `altis_companies` | Company names, codes, and locations for the portfolio selector |
| `altis_weather_weekly` | Weather data and delay scores shown alongside the forecast |
| `altis_profiles` | Current user's role (fetched once after sign-in) |

Reads use the PostgREST endpoint at `NEXT_PUBLIC_SUPABASE_URL/rest/v1/<table>`.
supabase-swift handles the `apikey` / `Authorization` headers automatically.

## Build instructions

### Prerequisites

```bash
brew install xcodegen    # if not already installed
```

### 1. Generate the Xcode project

```bash
cd ios
xcodegen generate
```

This reads `ios/project.yml` and writes `ios/Altis.xcodeproj/`.

### 2. Generate Secrets.swift

See the Credentials section above. The build will fail if `Secrets.swift` is missing.

### 3. Build for the simulator

```bash
xcodebuild \
  -project ios/Altis.xcodeproj \
  -scheme Altis \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -configuration Debug \
  build
```

Build products land in `ios/build/` (gitignored).

### 4. Run on the simulator

```bash
# Boot the simulator first if needed
xcrun simctl boot "iPhone 17"

# Install and launch
xcodebuild \
  -project ios/Altis.xcodeproj \
  -scheme Altis \
  -destination 'platform=iOS Simulator,name=iPhone 17' \
  -configuration Debug \
  -derivedDataPath ios/build \
  build

APP_PATH=$(find ios/build -name "Altis.app" | head -1)
xcrun simctl install "iPhone 17" "$APP_PATH"
xcrun simctl launch  "iPhone 17" com.altis.cashflow
```

## Shared backend

The iOS app and the Next.js web app talk to the same Supabase project and the
same set of `altis_*` tables. There is no separate iOS backend; the Supabase URL
and service configuration are identical. The demo accounts work in both apps
simultaneously.
